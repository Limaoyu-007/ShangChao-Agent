# 上朝：当前代码结构

Java 21 + Maven。当前有后台单次决策、控制台早朝，以及保留的工具型聊天示例。

## 三个入口

| 启动类 | 用途 | 调用关系 |
|---|---|---|
| `court.CourtRuntime` | 主动唤醒皇帝一次 | `EmperorAgent → ModelClient.chatText` |
| `court.MorningCourtRuntime` | 皇帝主持一场控制台早朝 | `MorningCourtSession → ModelClient.chatText` |
| `agent.Main` | 原来的工具型聊天示例 | `Agent → ModelClient.chat(messages, tools) → ToolRegistry` |

皇帝两个入口不注册工具、不经过工具执行循环。时间和政务由 Java 提供；调查决定不等于已经执行调查。

## 包与类的职责

- `model`：模型接口和百炼 HTTP 适配。客户端不持有 `ToolRegistry`，也不修改消息历史。
- `agent`：原工具型 Agent 和消息类型。为保持阅读与存储兼容，本次没有移动消息类。
- `tool`：工具定义、注册和实际执行。
- `court`：皇帝的两个运行场景、正式决策及文件存储。
- `store`：原聊天示例的会话存储，不是朝廷决策存储。

推荐阅读顺序：

1. `ModelClient`：无工具请求与工具请求如何区分。
2. `EmperorAgent`：一次后台决策的完整流程。
3. `MorningCourtSession`：会话开始、持续回应及提交消息的时机。
4. `CourtContext`：两个场景怎样读取共同资料，加入各自场景规则。
5. `DecisionParser`：后台输出解析成 `Edict`；旧版朝会输出解析成 `CourtReply`，拒绝非空决策。
6. `EdictStore`：正式记录如何读取、追加和原子保存。

`Message` 是模型协议消息，`role` 不是皇帝或朝臣身份。`system/user/assistant/toolResult` 工厂方法用于减少手写协议参数。保留 `tool_calls`、`tool_call_id` 的 JSON 名称，兼容旧会话文件。

`Edict` 是后台生成的圣旨，保留原来的五个 JSON 字段。`CourtReply` 是旧版朝会回应，兼容字段 `decision` 必须为 null，`ended` 表示是否退朝。两个早朝入口均不能写入圣旨。

## 配置与运行

在项目根目录运行，三个入口的工作目录应一致。

- `DASHSCOPE_API_KEY`：必需，在每个 IDEA 运行配置或进程环境中设置。
- `DASHSCOPE_MODEL`：可选，覆盖代码中的默认模型名。
- `DASHSCOPE_CHAT_URL`：可选，完整的 Chat Completions 请求地址，不是基础域名。
- `JAVA21_HOME`：使用 `build.cmd` 时指向 JDK 21；IDEA 也需选择兼容 JDK。

编译：`build.cmd`，或在 Maven 实际使用 JDK 21 时执行 `mvn -DskipTests compile`。

模型客户端设置了 20 秒连接超时、90 秒请求超时；错误响应会报告 HTTP 状态和简短错误字段。工具型 Agent 最多请求模型 12 轮，不自动重跑已执行过工具的流程。

## 状态与当前边界

- `court-governance-principles.txt`：用户人生最高准则，仅后台皇帝和朝会皇帝读取。
- `court-principles.txt`：皇帝专属身份、职责与权限；`court-affairs.txt`：用户当前情况、待处理问题和待核实信息，由用户维护，不自动改写。
- `court-state.json`：圣旨数组，沿用原有格式；历史记录原样保留，不补造来源。
- 后台每次唤醒读取新资料与最近三场朝会记录；早朝开场读取圣旨和政务快照。并行朝会事件保存到磁盘，但不恢复中断会话。
- 模型上下文展示最近 10 条圣旨，存储层仍读取完整数组。这不是完整的当前有效旨意系统。
- 旧版早朝请求或解析失败时，不提交这一轮消息。控制台目前会让异常退出，不自动重试；退出后的临时对话不会保存。
- `EdictStore` 用同目录临时文件原子替换快照，并以文件锁保护整个读取—追加—写入过程。竞争写锁时本次保存失败，不自动重试。`.lock` 文件会保留，操作系统锁在保存结束时释放。
- 文件锁只解决记录写入冲突，不解决重复决策或模型基于过期状态作决定。当前仍建议顺序运行后台与早朝；朝会中不会自动刷新后台新决定。
- 尚未加入定时调度、任务/复命状态、反馈摘要和前端；并行入口已有礼部、户部、工部、吏部四名大臣 Agent。

## 并行朝会入口

`court.parallel.ParallelMorningCourtRuntime` 是皇帝、大臣与用户共同议事的入口。模型并行生成行动提案，由协调线程串行提交事件；普通旧版本发言策略保持现有实现。

- 开场由程序宣读最近一份圣旨，没有圣旨时直接议事。先提交开场、宣旨事件，再广播一次触发模型思考。
- `CourtAction` 只允许 `SPEAK`、`SILENT`、`END_COURT`；仅皇帝可退朝，退朝判断必须基于最新快照。宣旨使用 `EDICT_ANNOUNCED` 事件，不再次写入圣旨存储。
- 暂不维护跨场次的已宣读状态，因此同一份圣旨可能在不同朝会上重复宣读；不区分宣读与生效状态。
- 每次请求的快照包含真实参与者 ID 清单及 `user`。无效 `targetId` 会被明确拒绝，不发布发言；`null` 表示向全体发言。
- 每轮自动行动达到 12 次后等待用户发言；整场模型调用达到 80 次后，不再接收新的议事输入，处理完在途结果后中止本场运行。这是系统中止，不冒充皇帝退朝。
- 皇帝读取人生最高准则和皇帝角色说明；大臣只读取自己的人设与公共会议协议。礼部侧重关系、沟通与生活体验，ID 为 minister；户部侧重收支、预算与资源分配，ID 为 finance。工部侧重技术与实施，ID 为 works；吏部侧重分工与排期，ID 为 personnel。四位大臣均未配置工具。

本轮验证以 JDK 21 编译和源码检查为范围；没有启动真实模型、学习通或其他外部工具，也没有改写现有决策数据。

## 朝会反馈存储（2026-09-24）

- `CourtRecordStore` 保存 `court-records/<场次UUID>.json`。每条事件保留序号、事件ID、类型、发言者、内容、回应对象和 ISO 时间字符串。
- 并行朝会的协调线程在开场、宣旨、用户发言、Agent 发言和退朝提交后保存本场快照，再展示和广播。模型未被接受的提案、沉默和未出队的输入不写成公开事件。
- 同场仅由一个协调线程写入，使用同目录临时文件原子替换。保存失败会报错并中止本场，上一次完整文件保留；未保存成功的最新事件不能保证恢复。
- `/exit`、输入关闭、额度耗尽不伪造退朝事件，已保存记录保留。旧版 `MorningCourtRuntime` 暂未接入记录存储；反馈闭环使用 `court.parallel.ParallelMorningCourtRuntime`。
- `EmperorAgent` 每次从磁盘读取最近更新的三场完整记录（尚未做摘要或字符截断），所以重启后仍有反馈。无记录时提供空数组；JSON 损坏会明确报错，不悄悄丢弃。
- 用户报告、大臣建议和推测保留来源，由皇帝结合时间判断；发言不自动成为事实或圣旨。没有退朝事件不代表达成共识。
- 原有政务文本与历史圣旨不自动更新；建议仍按“并行早朝 → 退出 → 后台单次运行”的顺序使用。

本次完成源码检查与 JDK 21 Maven 编译，未进行真实模型联调或跨进程行为实测。
